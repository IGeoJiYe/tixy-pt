# 티켓 발급, 모바일 티켓, 수령 안내 정책

## 문서 목적
- 이 문서는 TIXY의 실제 티켓 생성 흐름을 기준으로 모바일 티켓, 예매 내역, 배송/수령 문의에 답변하기 위한 정책이다.
- 현재 TIXY 백엔드는 결제 성공 후 티켓 레코드를 생성하지만, 별도의 실물 배송 추적 API나 배송 상태 API는 확인되지 않는다.
- 따라서 배송 완료, 운송장, 현장 수령 확정 등은 단정하지 않는다.

## TIXY 티켓 발급 흐름
1. 좌석이 `HELD` 상태인 동안 주문이 생성된다.
2. 입금 웹훅이 정상 처리되면 주문은 `CONFIRMED`가 된다.
3. 해당 좌석 세션은 `RESERVED` 상태가 된다.
4. 좌석별 티켓이 생성되고 티켓 ID와 좌석 라벨이 응답에 포함된다.
5. 생성 직후 티켓 상태는 `PENDING`으로 저장된다.

## 티켓 관련 상태 이해
- 좌석 상태 `AVAILABLE`: 선택 가능한 좌석
- 좌석 상태 `HELD`: 고객이 임시 확보한 좌석, 5분 내 결제 필요
- 좌석 상태 `RESERVED`: 결제가 확인되어 예약된 좌석
- 티켓 상태 `PENDING`: 티켓 레코드가 생성된 초기 상태
- 티켓 상태 후보: `CONFIRMED`, `USED`, `CANCELLED`, `REFUNDED`, `EXPIRED`

## 모바일 티켓 문의
### 먼저 확인할 항목
- 고객이 로그인 상태인지
- 예매가 결제 완료 상태인지
- 입금 후 충분한 시간이 지났는지
- 예매 내역 또는 마이티켓 화면에 공연이 표시되는지
- 같은 계정으로 예매했는지

### 안내 기준
- 입금 직후라면 웹훅 처리 지연 가능성을 안내한다.
- 주문이 아직 `PENDING`이면 모바일 티켓이 보이지 않을 수 있다.
- 좌석 홀드가 만료되었거나 주문이 `EXPIRED`라면 티켓이 정상 발급되지 않을 수 있다.
- 상담원 확인 전에는 티켓이 정상 발급됐다고 단정하지 않는다.

### 응답 예시
- "모바일 티켓은 결제 확인 후 예매 내역에 반영됩니다. 입금하신 지 얼마 되지 않았다면 처리 시간이 조금 걸릴 수 있어요."
- "마이티켓에 보이지 않는 경우 로그인 계정, 주문번호, 트랜잭션 ID를 확인해 주시면 상담원이 발급 상태를 확인해 드릴게요."

## 배송 티켓 문의
- 현재 확인된 TIXY 백엔드에는 배송 상태, 운송장, 배송지 변경 API가 없다.
- 실물 배송 여부는 공연/운영 정책 확인이 필요하다고 안내한다.
- 배송 주소 변경 가능 여부는 배송 시작 전후와 운영 정책에 따라 달라질 수 있으므로 단정하지 않는다.

### 응답 예시
- "현재 예매 건이 모바일 티켓인지 실물 배송 대상인지 먼저 확인이 필요합니다."
- "배송지 변경 가능 여부는 배송 시작 여부에 따라 달라질 수 있어 상담원이 예매 정보를 확인한 뒤 안내드릴게요."

## 현장 수령 문의
- 현재 확인된 TIXY 백엔드에는 현장 수령 확정 API가 없다.
- 현장 수령 가능 여부는 공연장 운영 정책과 예매 상태 확인이 필요하다.
- 고객에게 예매 내역과 본인 확인 수단 준비를 안내할 수 있다.

## 바로 확답하면 안 되는 상황
- "배송이 시작되었습니다"라고 단정하는 것
- "운송장 번호는 이렇습니다"라고 임의로 말하는 것
- "모바일 티켓은 정상 발급됐습니다"라고 확인 없이 단정하는 것
- "현장 수령 가능합니다"라고 운영 확인 없이 말하는 것
- 티켓 상태가 `PENDING`인데 최종 확정 티켓이라고 단정하는 것

## 답변 가이드
- 모바일 티켓은 결제 확인과 예매 내역 반영 여부를 중심으로 안내한다.
- 배송/현장 수령은 실제 운영 확인이 필요하다고 말한다.
- 고객에게 주문번호, 예매 계정, 트랜잭션 ID, 공연명/회차를 요청한다.
