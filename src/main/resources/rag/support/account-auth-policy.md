# 계정, 본인 확인, 지갑 주소 정책

## 문서 목적
- 이 문서는 TIXY의 회원/인증/지갑 주소 흐름을 기준으로 계정, 로그인, 예매 내역 확인, 지갑 주소 문의에 답변하기 위한 정책이다.
- 계정 정보와 예매 내역은 개인정보와 결제 정보에 연결되므로 본인 확인 전에는 상세 내역을 제공하지 않는다.
- 고객에게 답변할 때는 내부 결제 처리 방식, 로그인 처리 방식, 데이터 처리 용어를 그대로 쓰지 않는다.
- 쉬운 표현으로 바꿔 말한다: "입금 확인", "입금 내역 확인", "로그인 상태 해제", "입금에 사용한 주소".

## TIXY 계정 구조 요약
- 회원은 이메일, 이름, 전화번호, 역할, 지갑 주소, 포인트 정보를 가진다.
- 회원가입 시 포인트는 0으로 시작한다.
- 로그인은 이메일/비밀번호 기반으로 진행된다.
- 로그아웃은 로그인 상태를 안전하게 해제하는 방식으로 처리된다.
- 고객 역할은 일반 사용자, 관리자, 슈퍼 관리자 역할로 나뉠 수 있다.

## 지갑 주소 정책
- 주문 생성 전 고객 계정에 지갑 주소가 있어야 한다.
- 지갑 주소가 없으면 주문 생성이 실패할 수 있다.
- 지갑 주소는 로그인한 회원의 `/members/v1/wallets` 흐름에서 갱신된다.
- 지갑 주소는 입금 내역 확인과 포인트 보상 처리에 사용된다.

## 예매/결제 확인 시 본인 확인 기준
### 먼저 확인할 항목
- 고객이 로그인 가능한 상태인지
- 문의 계정이 실제 예매 계정인지
- 주문번호, 예매번호, 공연명, 회차 일시 중 하나 이상을 알고 있는지
- 지갑 결제 문의라면 입금에 사용한 주소 일부, 입금 시각, 입금 완료 화면을 확인할 수 있는지

### 안내 기준
- 본인 확인 전에는 예매 좌석, 결제 금액, 지갑 주소 전체, 이메일/전화번호 전체를 말하지 않는다.
- 타인 명의 예매 내역은 안내하지 않는다.
- 지갑 주소는 필요 시 일부 마스킹해서 확인한다.
- 고객이 계정 접근을 못하면 이메일/전화번호 등 최소 정보 확인 후 상담원 연결을 안내한다.

## 포인트 관련 안내
- 입금 내역과 예매 정보를 바로 연결하지 못했거나 결제 가능 시간이 지난 상황에서 입금 금액이 포인트로 보상될 수 있다.
- 포인트 적립 여부는 지갑 주소와 입금 확인 결과 확인이 필요하다.
- 포인트를 현금 환불과 동일하게 확정해서 설명하지 않는다.

## 바로 확답하면 안 되는 상황
- 본인 확인 전 예매 내역을 알려 주는 것
- 타인 계정의 주문/티켓 정보를 안내하는 것
- 지갑 주소 전체를 채팅에 노출하는 것
- 포인트 적립 또는 환불 처리가 완료됐다고 확인 없이 말하는 것
- 로그인 실패 원인을 단정하는 것

## 답변 가이드
- "본인 확인이 먼저 필요하다"는 점을 짧고 차분하게 안내한다.
- 필요한 정보는 이메일 전체가 아니라 로그인 계정 여부, 주문번호, 공연명/회차 등으로 시작한다.
- 결제 문의는 주문번호, 입금 시각, 입금에 사용한 주소 일부를 요청하되, 채팅에 민감정보를 과도하게 남기지 않도록 안내한다.

## 응답 예시
- "예매 내역은 개인정보와 연결되어 있어 본인 확인이 먼저 필요합니다. 로그인한 계정과 주문번호 또는 공연명/회차를 알려 주시면 상담원이 확인해 드릴게요."
- "지갑 주소가 등록되지 않은 계정은 주문 생성이 어려울 수 있습니다. 마이페이지에서 지갑 주소 등록 여부를 확인해 주세요."
- "입금했는데 예매가 보이지 않는 경우 주문번호, 입금 시각, 입금에 사용한 주소 일부를 알려 주세요. 전체 주소 노출이 부담되면 앞뒤 일부만 먼저 알려 주셔도 됩니다."
